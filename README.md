# StyleGuru – AI-Powered Virtual Shopping Assistant

Case Study 61: a multimodal AI assistant for a fashion retailer that understands what a
customer wants, from text or a photo, and recommends suitable products from the store's catalogue.

## Running it

1. Put your Gemini API key in a file named `.env` in this folder:

   ```
   GEMINI_API_KEY=your-key-here
   ```

2. Double-click `run.bat`, or run:

   ```
   python -m venv .venv
   .venv\Scripts\python -m pip install -r requirements.txt
   .venv\Scripts\python -m uvicorn app.main:app --port 8000
   ```

3. Open http://localhost:8000

## Things to try

- "A navy kurta under ₹1500 for a wedding"
- Follow up with "what shoes would go with the first one?"
- Click the photo button, upload a picture of a garment and ask "find something like this"
- Open **My style**, set a size and favourite colours, and repeat a search to see the ranking change
- Open **Privacy**, switch personalisation off, or delete your data

## How it works

```
Browser (static/)                 Server (app/)                     Google Gemini
-----------------                 -------------                     -------------
chat + photo  ───────────────►  main.py     strips photo metadata
profile (only if                assistant.py ─────────────────────►  reads text + photo,
personalisation is on)                       ◄─────────────────────  calls search_products
                                catalog.py   filters, checks stock,
product cards  ◄───────────────              ranks for the shopper
```

1. The browser sends the message, the optional photo and the conversation so far.
2. Gemini turns them into structured requirements (product type, colour, occasion, budget,
   size) and calls the `search_products` tool. It can call it several times, for example
   once per item in an outfit.
3. `catalog.py` filters the catalogue, checks stock in the shopper's size, ranks the
   matches using the style profile, and records why each one was picked.
4. Gemini writes a short reply; the browser shows the products as cards.

The model never invents products: everything it mentions comes from the tool's results.

## How the problem statement is addressed

| Requirement | Implementation |
|---|---|
| Visual information | Photo upload. Gemini identifies the garment's type, colour and style, then searches for similar or complementary products. |
| User preferences | Requirements are extracted from the conversation, carried across turns, and shown as removable chips above the results. |
| Product availability | Stock is tracked per size. Results are checked against the shopper's size; sold-out matches are flagged and in-stock alternatives are ranked first. Low stock is called out. |
| Personalisation | A style profile (who they shop for, sizes, budget, favourite colours, liked and hidden items) re-ranks results. Each card says why it was recommended. |
| Privacy | See below. |

### Privacy measures

- **Consent**: a photo can only be attached after the shopper agrees to a notice explaining
  that it is sent to Google Gemini.
- **Data minimisation**: photos are resized and re-encoded in memory, which removes EXIF
  metadata such as GPS location. They are never written to disk.
- **No server-side storage**: the server keeps no accounts, sessions, chat logs or
  database. The browser sends the conversation with each request.
- **Local profile**: the style profile lives in the browser's local storage only.
- **Control**: personalisation can be switched off, in which case the profile is not sent
  to the server at all. "Delete all my data" wipes everything.
- **Transparency**: the Privacy panel shows exactly what is stored on the device.
- **Model instructions**: the assistant is told to describe only clothing, never the person
  in a photo, and never to ask for personal details.

Limitation: photos and messages are processed by a third-party cloud model (Google Gemini),
so Google's data policies apply to them. A fully private version would run a local vision
model instead.

## Project layout

| Path | Purpose |
|---|---|
| `app/main.py` | Web server and API endpoints |
| `app/assistant.py` | Gemini prompt, tool definition and conversation loop |
| `app/catalog.py` | Catalogue search, availability and personalised ranking |
| `static/` | The web page (HTML, CSS, JavaScript) and product photos |
| `data/catalog.json` | 84 products with price, sizes and stock |
| `scripts/build_catalog.py` | Rebuilds the catalogue from the dataset |

## Data

Product names, attributes and photos come from the
[Fashion Product Images](https://www.kaggle.com/datasets/paramaggarwal/fashion-product-images-small)
dataset. The dataset has no prices or stock levels, so those are generated by
`scripts/build_catalog.py` with a fixed random seed.

## Gemini models and free-tier limits

The assistant tries `gemini-flash-latest` first, then `gemini-3.5-flash`, then
`gemini-flash-lite-latest`. Each has its own free-tier quota, and the best model's is small
(20 requests per day at the time of writing; one chat message uses two or more requests).
When a model is out of quota or overloaded the app moves to the next one automatically, so
the chat keeps working, with slightly plainer replies. Set `GEMINI_MODEL` in `.env` to
choose a different first model.
